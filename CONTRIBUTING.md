# Как внести вклад

Спасибо, что хотите помочь! Небольшие исправления сразу присылайте pull request'ом.
Крупные изменения сначала обсудите в issue, чтобы не делать работу зря.

## Окружение

```bash
python -m venv .venv && . .venv/bin/activate
make install
make check        # ruff, mypy --strict, pytest — то же, что в CI
```

Для тестов на PostgreSQL задайте `TEST_DATABASE_URL`. База будет очищена!

## Правила

- **Слои.** `domain` не импортирует ничего, кроме стандартной библиотеки.
  `application` зависит только от `domain` и `ports`. Фреймворки и драйверы
  живут в `adapters`, а связываются в `bootstrap.py`
  (см. [docs/architecture.md](docs/architecture.md)).
- **Прозрачность.** Шлюз не меняет байты запроса и ответа и не добавляет своих
  заголовков. Изменения, которые это нарушают, не принимаются.
- **Токены.** Токен бота не должен попадать в логи, базу, метрики и тексты
  исключений. Новый код, который пишет куда-либо данные запроса, должен
  сопровождаться тестом на это.
- **Путь запроса.** На пути запроса никакого ввода-вывода, кроме самого
  проксирования. Работа с хранилищем идёт только в фоновых задачах.
- **Тесты.** Новое поведение сопровождается тестом. Ядро тестируется на фейках
  из `tests/support/fakes.py`, адаптеры — интеграционными тестами.
- **Стиль.** Код форматирует `ruff format`, а `mypy --strict` должен проходить.
  Комментарии и сообщения коммитов пишем на русском.

## Миграции

Новая миграция — это новый файл `NNN_name.sql` в
`src/tg_relay/adapters/storage/postgres/migrations/`. Уже выпущенные миграции
не редактируются.
